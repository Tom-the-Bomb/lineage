# Timeline, station and map sources

Research register assembled **23 September 2026** for all eight systems currently in the repository.

This file preserves references recovered from earlier research and adds newly located corroboration. It indexes **every current event entry and every legend line**, including historical predecessors, trams, light rail and gondolas. It also records sources for station/transfer identities, kilometres and drawn geography.

The Tokyo, Shenzhen, Hangzhou and Guangzhou line-history references were largely recovered from earlier map-building research. Most Hong Kong, Shanghai, Taipei, Singapore and Foshan line-history links were located again for this register; they should not be represented as a recovered original bibliography. The existing spec also preserved several original Hong Kong and geographic references.

**Coverage is not the same as verification.** Some entries still have only a secondary chronology, some exact days are placeholders, and some historical distances/coordinates are estimates. Those limitations are recorded below; this is not a claim that every existing value has a reliable primary citation. No timeline data or geometry was changed while assembling this register.

## How to read and maintain this file

- **Recovered** means the reference was found in the existing spec, earlier research files or their bibliographies. It does not mean the original author of every asset can be proven to have used it.
- **New** means a reference located for this register; it corroborates existing data rather than proving its original provenance.
- **Recovered citation** links preserve useful original notices and contemporary reports cited by the earlier research. They have not all been independently reopened; a link is not a claim of successful retrieval. Archives and WeChat in particular may block automated access.
- **Secondary chronology** means a line/station history, usually Wikipedia. It is useful for locating dated primary evidence, but must not settle a disputed day merely because the repo agrees with it.
- **Unresolved / unverified day** identifies a specific claim that still needs evidence. A source for a line opening does not automatically substantiate a rename, delayed station or paid-area change listed in the same event.
- Event-table descriptions below are an inventory copied from the repository, **not quotations from the linked sources**. Sources apply only to their stated subject. The table deliberately preserves questionable entries so they can be corrected in the data after verification.
- Prefer operator notices and dated maps; then government records, contemporary reporting and scholarly histories; then secondary timelines and their footnotes. A planned opening, trial without public passengers, construction completion or ceremony is not necessarily first passenger service.

### What needs a source

| Stored fact                                                       | Evidence to use                                                                                                                             |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `events.json`: each date and each description                     | Event index below; resolve each independent claim, not just the first description on the date.                                              |
| `lines.json`: historical names and start/end dates                | Line histories and dated naming notices; corporate establishment, service takeover and public renaming can occur on different days.         |
| SVG track labels: opening, removal, reassignment                  | Opening/withdrawal notices and historical route diagrams; end dates are exclusive, so first absent day may be the day after last operation. |
| SVG station labels: name, opening, relocation, marker replacement | Line station tables plus station-specific histories and operator plans; a marker upgrade is not a newly opened physical station.            |
| SVG `data-lines`, connectors and station identity                 | Dated interchange diagrams and fare-area notices. Walking connection, continuous fare and shared paid area are different facts.             |
| SVG `data-km`                                                     | Published operating section length, with rounding/allocation documented; not the length of the Bézier path.                                 |
| SVG route/station/water coordinates                               | Original map provenance, engineering alignment and mapped geographic features; modern geometry does not establish historical geometry.      |
| Colours, logos and compact interchange shapes                     | Operator wayfinding/map and original artwork. These are presentation choices, not extra historical events.                                  |

The date boundaries in all eight `map.svg` files (station/track labels and `data-lines`) and their `lines.json` legends were compared with their `events.json`: **none fall on a date absent from the event index**. This checks coverage of dates, not correctness or completeness of every description. Source links for the line station tables also cover intermediate stations omitted from event prose.

Use [the map data spec](map-data-spec.md#11-sources-and-verification) for scope and parsing. This is a build history: maintenance, accidents and temporary operating suspensions normally do not erase built track. Public previews count in several existing systems; the inconsistent treatment in Singapore/Taipei needs an explicit decision, documented below.

## Accuracy gaps to keep visible

1. **Hong Kong:** 1913 Sheung Shui halt and other early KCR/Sha Tau Kok halts are not fully inventoried; Hung Hom 1921 closure, Kowloon Tong 1982 opening and 1996 names need exact-day evidence. Several 1960s rename dates encode only a known year. Historical KCR geometry and Light Rail stage lengths are estimates.
2. **Shanghai:** early surface-alignment replacements, Maglev first public service, paid-area passage dates and exact English naming rollouts need stronger primary evidence. The English timeline and other histories disagree on the first Line 3 day.
3. **Taipei:** extension dates do not by themselves prove when modern combined line names became official. Some stored section kilometres differ from operator historical tables. Circular Line trial rides also raise the preview-policy question.
4. **Singapore:** the repo uses regular opening dates where LTA records earlier public previews; in particular CCL6 on 4 versus 12 July 2026. Early East–West naming and exact section kilometres need checking beyond a current network map.
5. **Shenzhen:** January 2025 SIAT/SUAT rename day and December 2025 Grand Theater passage day are not established. Simplified tram/Skyshuttle interchange markers deliberately compress real walking distances.
6. **Hangzhou:** October 2019 English Yuhang rename is month-only. Airport/railway-station continuous fares must not be mistaken for physically joined paid areas.
7. **Guangzhou/Foshan:** May/November 2006 and September 2021 naming rollouts lack exact days; historical tram previews require their timetable. Line 12 length definitions differ between sources.
8. **Across systems:** a published present-day total does not prove each historical `data-km` allocation, and a geographic SVG is not a survey. Original artwork provenance remains incompletely recovered for several older systems.

### SVG geography, identities and measurement limits

The SVG retains the title “MTR system map in English released to the public domain”, but its exact upstream Commons revision has not been recovered. Do not treat that embedded statement as full provenance for later additions. The background geography was replaced on 23 September 2026 using the sources below; the KCR/Sha Tau Kok reconstructions still require historical maps rather than modern track data.

- Coastlines and islands: © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), data under [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/), from [Geofabrik's Guangdong extract, including Hong Kong and Macau](https://download.geofabrik.de/asia/china/guangdong.html), snapshot `guangdong-260923.osm.pbf` (data through `2026-09-23T20:22:04Z`). Uses the mapped `natural=coastline` ways, including airport reclamation, harbour quays, Deep Bay and outlying islands; small offshore polygons below 0.5 SVG square units are omitted for legibility.
- Hong Kong/Shenzhen land colours: [Hong Kong administrative boundary, OSM relation 913110](https://www.openstreetmap.org/relation/913110). The visible border river uses the mapped water polygon [relation 9791660](https://www.openstreetmap.org/relation/9791660), rather than an invented gap between the land shapes.
- Registration: WGS84 coordinates fitted to the existing map using modern East Rail, Tsuen Wan, Tung Chung and Tuen Ma station control points. Coastlines were simplified with a topology-preserving tolerance of 0.25 SVG units, without moving railway paths or stations. This improves the background's geographic accuracy within the original map's approximate projection; it is not a survey. The background shows **present-day geography throughout playback**, not historical reclamation stages.

- Sha Tau Kok and early KCR: museum booklet and annual reports above. Historic curves and station positions remain approximate; a date citation does not certify their coordinates.
- Modern geographic cross-checks: [East Rail](https://www.openstreetmap.org/relation/4248589), [Tsuen Wan](https://www.openstreetmap.org/relation/269669), [Tung Chung](https://www.openstreetmap.org/relation/5317704), [Tuen Ma](https://www.openstreetmap.org/relation/6102298), [XRL](https://www.openstreetmap.org/relation/9405634).
- The XRL geometry was corrected through Kwai Chung/Shek Kong using mapped track plus the LegCo alignment. It continues into Shenzhen at the SVG boundary; only Hong Kong mileage is counted. Old Beacon Hill and Tsim Sha Tsui approaches are historical reconstructions, not current OSM railway.
- Light Rail is simplified. The documented allocation is 36.2 km today, with 4.4 km for 2003 extensions, 3.2 km for earlier Tin Shui Wai track and 28.6 km for the older Tuen Mun/Yuen Long area. Splits within that last group were prorated by drawn length: **estimates, not measured historical engineering lengths**.

Exact upstream SVG revision/author has not been recovered. Existing rivers and the original metro alignments are inherited illustration; the Shanghai timeline is a history source, not geographic evidence.

- Songjiang University Town’s short branch and local offsets at Sports Center depict simplified tram connections. They must not be read as survey-accurate co-location.
- Shanghai Railway Station, West Nanjing Road, Caoyang Road and other walking transfers need separate paid-area identities. A shared name or fare concession does not justify merging all markers or highlighting every line’s platforms.
- The early Jinjiang Park/Shanghai South and Zhangjiang High-Tech Park replacement alignments require historical maps. Modern line geometry cannot independently verify removed surface stations.

## Geography and artwork: shared limitations

[OpenStreetMap contributors](https://www.openstreetmap.org/copyright) provide the modern mapped alignments linked above. The listed object IDs were recovered from the earlier geographic research; their live versions may change. Use the object history or a dated snapshot when reproducing an edit. These are crowdsourced spatial checks, not railway engineering certification or proof of historical opening dates.

The original supplied SVG and later adjustments are separate layers of provenance. A Commons licence applies to its identified artwork, not automatically to every later background, logo or geometry addition. Follow the linked file pages for the full attribution/file history. Exact original source revisions remain an explicit gap where they could not be recovered; a visually similar map is not sufficient attribution.

The maps deliberately simplify curves, parallel tracks and interchange capsules. `data-station` IDs are repository identifiers, not official station codes. Colours may be inherited or adapted. Neither identifier spelling, symbol shape nor a tiny local display offset needs a historical event, but the station identity and line membership they represent do.

### Length reconciliation still required

- The line tables show **stored** active kilometre sums, not a claim that every figure was obtained directly from a primary source.
- Check each opening section against its published _operating_ length; project length can include unopened stations, sidings, depots or future extensions.
- Preserve the source precision before rounding to the SVG’s one decimal. When a sourced total is split between paths solely for animation/relocation/line reassignment, record the allocation method rather than presenting each split as independently measured.
- Historical KCR/Light Rail estimates, Tokyo shared corridors, Taipei differing historical section figures and Guangzhou Line 12’s 27.9/28.8 km discrepancy particularly need this treatment. A matching modern total cannot validate all earlier totals.
- Station counts are derived from the spec’s identities and simplification policy. They will not always equal an operator’s published “stations”, which may count interchange platforms once per line or include all intermediate LRT/tram stops.

## Updating the register

For a new or corrected fact, update the relevant event row **and** the applicable line/station/geometry entry. Record the actual passenger date, source publication date, exact article/PDF page or chronology entry, and what the source establishes. Prefer a stable article URL over a homepage/search result. Preserve an archive URL for an inaccessible original, and label a reported/approximate date honestly.

Do not promote a recovered citation to “verified” without reading the relevant passage. Resolve mixed rows description by description; e.g. a line-opening announcement may substantiate the route but say nothing about the English name rollout or whether a transfer is within the paid area. Check SVG/legend boundaries against the revised event date after a data correction.

This register is documentation only; it is not imported by the application. It does not add sources/network/audit JSON to the runtime data model.
